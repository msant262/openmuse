Generate calibrated units with `python3 -m executor.deployment`; static per-user RAM limits are intentionally absent. `okami-bots.slice` is under `okami.slice`, and `okami-bots-u1003.slice` is below that shared ancestor. Jobs, their descendants, and the registered D-Bus/session service use that ancestry. Supervisors use `system.slice`.

The generated session service is a D-Bus lifetime service for milestone 6. It does not claim desktop, capture, input, or browser readiness. Milestone 7 replaces its executable with the tested private graphical session while retaining its UID, slice, private runtime directory, and isolation. Existing GNOME RDP and personal user managers remain untouched.

The generated `sleep-target.conf` belongs in `/etc/systemd/system/sleep.target.d/okami.conf`. It requires each registered root-only suspend hook to confirm containment through its supervisor's private Unix socket before sleep. Resume always requires a fresh protocol handshake and receipt reconciliation. Install the hooks only together with their running supervisors.

Job services use `Type=exec` and `RemainAfterExit=yes`. The supervisor treats `active/exited` as a retained terminal result after actual execution proof and descendant cleanup, commits its receipt, then stops that fixed unit to allow collection. Missing units remain semantically unknown. Cleanup-confirmed journal receipts reconcile owned host-budget reservations on restart even after receipt ACK. Optional missing fixed inaccessible paths use systemd's `-` prefix; paths that exist still receive deny mounts.

The local `test_lifecycle.py --owned-units` acceptance runner requires explicitly authorized root execution. It refuses pre-existing fixed proof units, uses nobody and temporary private paths, and stops only its own controller/hashed job units. It reports retained short success, exit 7, cancellation, timeout and cleanup. This does not replace Lenovo's real-account, controller-death, descendant/OOM and calibrated-resource acceptance.
