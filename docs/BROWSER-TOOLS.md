# Personal browser and Take control

The native agent now uses Playwright directly. Set `BROWSER_WORKER_URL` and `BROWSER_WORKER_TOKEN` as described in the existing worker setup. No Browser Use service or extra cloud account is required. Keep the worker private and retain its `/data` volume.

The chat and durable task worker offer:

- `browser_navigate`: open a public URL and return numbered controls.
- `browser_snapshot`: read the current page, bounded text and up to 150 visible controls, including supported child frames. Password values and hidden inputs are omitted.
- `browser_act`: click, fill, select, press or scroll using the exact snapshot ID and element number. Successful actions return fresh numbers. Old, disconnected or changed controls are rejected; the model cannot pass selectors, JavaScript or an approval override.
- `browser_screenshot`: return safe page metadata and an owner-scoped durable screenshot reference. JPEG bytes (at most 1 MiB and 1280 × 800) are stored once below `DATA_DIR/browser-screenshots` and hydrated only for the latest model image at dispatch. Reconnect/history receipts never contain image bytes. The model transport promotes the latest screenshot into a user image message for Responses, Chat Completions and subscription Responses. Providers never fetch a signed console URL. Vision remains dependent on the configured model; use numbered snapshots with text-only models.

`browse_web` and durable `read_web` remain available for existing demo and reading flows. Every owner has one default persistent browser/profile shared by new chats, tasks and the app's browser opener. Explicit session IDs must belong to that owner. Existing chat profiles are adopted on first use when there is no default; other saved profiles remain accessible. Closing/restarting a session retains cookies and local storage; restarting the worker reopens the same UUID/profile as needed.

The worker owns Chromium shutdown on SIGTERM/SIGINT/SIGHUP: it drains queued work, saves active browser state, closes the profiles and then exits. A clean exit means those saves completed. A failed save or the 30-second shutdown deadline exits nonzero; backups must reject that exit and investigate storage before proceeding. The isolated demo worker uses the same behavior with a 10-second deadline.

Browser cards remain accessible while the model runs. Open **Watch / take control** from the card or Browser workspace. The live console initially watches the agent. **Take control** disables queued agent mutations and enables tapping, typing, keyboard buttons and scrolling. **Hand back to agent** invalidates old numbered references and restores agent control. Closing the console preserves the chosen mode. Human mode is saved across worker restart, so recovery does not silently grant control to the agent.

Durable tasks that encounter takeover pause with their checkpoints intact and resume automatically after handback. A chat reply that already ended while waiting for takeover needs the next user message, such as “continue”; handback alone does not start a new chat run. The console states this distinction. Taking control immediately gates queued dispatches; an operation already dispatched to Chromium may finish before takeover acknowledgment. OpenMuse does not claim to undo an in-flight action.

The existing queue, public-address DNS checks, request guards and DNS-pinning egress proxy remain active for production browser operations. Private/local/metadata destinations, unsupported protocols/ports and WebSockets remain blocked. Human navigation shares the same guards. The console renders screenshots, so remote website JavaScript never executes inside the phone's console document.

Money controls are conservatively blocked until the native approval executor is installed in the permissions milestone. The guard checks real English, Portuguese and German labels and associated form submitters, including Enter submission. The trusted service receives a canonical binding to session/snapshot/element/action/URL/document fingerprint and form/page digest; the model sees only a safe approval-required message. Matching labels is a heuristic and cannot identify every custom or malicious payment UI. No caller boolean bypass exists. Any later approval executor must revalidate the binding under the session queue, reject takeover/page drift and retain single-use receipts; stale references after worker restart require a new preparation.

Run `pnpm test` for server/model/ownership/lease contracts and `pnpm test:browser` for real Chromium DOM actions, phone-sized console interaction, profile persistence, production proxy navigation and takeover ordering. Install the worker's pinned browser first with `pnpm --dir apps/worker exec playwright install chromium`. Tests inject fixture HTML only into standalone Playwright pages; the production manager has no SSRF bypass option.

Current limits: one controlled tab per session (popups are closed), DOM snapshots cover supported visible controls rather than canvas-based controls, native file dialogs are not agent actions, and live websites may require human CAPTCHA/MFA. The transport includes only the latest screenshot per model request; durable thread history stores small asset references; distinct screenshots consume disk once in `DATA_DIR/browser-screenshots`, which must be included with the whole data directory in backups. Phone-sized console behavior is tested in desktop Chromium; physical iOS/Android devices and live account logins are not verified by that test.
